# Chat Assistant

A streaming chat interface built with Next.js. Users type a query and receive a streamed, token-by-token response that simulates an AI assistant

## Tech stack

- **Next.js 16** (App Router, no Turbopack)
- **React 19**
- **TypeScript**
- **Tailwind CSS v4**
- **Zustand** — granular store selectors to isolate re-renders during streaming

## Architecture overview

```
src/
├── app/
│   ├── layout.tsx
│   ├── page.tsx                    # Server component shell
│   └── api/
│       ├── chat/route.ts           # POST — streams tokens via ReadableStream
│       └── chat/abort/route.ts     # POST — server-side hook for stream cancellation logging
├── components/
│   ├── ChatMessages.tsx       # Scroll container (no store subscription); renders MessageList + StreamingBubble
│   ├── MessageBubble.tsx      # Completed message bubble, memoized (no store subscription)
│   ├── StreamingBubble.tsx    # In-progress token render, isolated re-renders
│   └── ChatInput.tsx          # Textarea + send, subscribes to streamingState only
├── hooks/
│   └── useAutoScroll.ts
├── lib/
│   ├── streamAssistantResponse.ts  # Mock token generator (server-only)
│   └── chatApi.ts                  # Client API: stream fetch + abort notify
├── store/
│   └── chatStore.ts           # Zustand store + exported selectors
├── styling/
│   ├── fonts.ts
│   └── globals.css
└── types/
    └── chat.ts                # Message, Role, StreamingState, ChatStore
```

The API route wraps the mock generator in a `ReadableStream` and returns `text/plain` with cache headers that prevent proxy buffering. The client reads chunks with `response.body.getReader()` and writes them straight into `streamingContent` in the Zustand store on every chunk. Only `StreamingBubble` subscribes to `streamingContent`; `ChatMessages` is a subscription-free layout wrapper, so the committed message list never re-renders during streaming.

## Prerequisites

- Node.js 18+
- npm (or yarn / pnpm / bun)

No external API keys are required — responses are generated by a local mock function.

## Development

```bash
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000). The page hot-reloads on file saves.

## Production

Build and start a production server:

```bash
npm run build
npm start
```

The production server runs on port 3000 by default. To use a different port:

```bash
npm start -- -p 8080
```

## Testing

Unit tests run on [Vitest](https://vitest.dev/) (jsdom environment, with `@testing-library/react` for the hook tests).

```bash
npm test          # Run the suite once
npm run test:watch  # Re-run on change
```

Coverage spans the core streaming logic:

- **`chatStore`** — send / abort / error lifecycle, `streamingContent` accumulation, abort notification, and selectors
- **`chatApi`** — request shape, chunk decoding (including multi-byte splits), error paths, and fire-and-forget `notifyAbort`
- **`/api/chat` & `/api/chat/abort`** — body validation and streaming headers
- **`useAutoScroll`** — scroll-on-trigger, disable-on-scroll-up, re-enable per turn

## Deploying

The app is a standard Next.js project and can be deployed to any platform that supports Node.js server rendering:

- **Vercel** — connect the repo; zero config required.
- **Self-hosted** — run `npm run build && npm start` on any Node.js 18+ host. No environment variables are needed for the base build.
